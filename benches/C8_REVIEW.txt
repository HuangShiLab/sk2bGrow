C8 复核 —— 建议两个选项都先不要采纳，有一个更简单的解释
================================================================

先说结论：C8 的证伪条件判定我同意，低覆盖档的改善是真的。但报告里
5-10x 的退步**不是 overdispersion**，而且 v_shape 基线复现不了我们已发表
的 arm A。这两件事都要先处理，采纳决策才有意义。


1. 阻断项一：v_shape 基线不是 arm A
----------------------------------------------------------------

C8 的 v_shape 与已提交的 benches/zheng2020/RESULTS.txt 里的 arm A：

  深度      r  (C8 / 已提交)     slope            阴性对照
  0.5x    0.568 / 0.913      0.255 / 0.615     0.379 / 0.260
  1.0x    0.906 / 0.981      0.673 / 0.779     0.358 / 0.077
  2.0x    0.935 / 0.982      0.748 / 0.840     0.152 / 0.097
  5.0x    0.980 / 0.979      0.834 / 0.920     0.076 / 0.060
 10.0x    0.985 / 0.968      0.928 / 0.951     0.039 / 0.046

低覆盖档差距极大：0.5x 的 r 是 0.568 对 0.913，1x 的阴性对照是 0.358 对
0.077（差 4.6 倍）。5-10x 才接近。

同一个估计器、同一批数据，不该有这个差距。**在解释清楚之前，
"GLM 优于 v_shape" 这个判定的对照组身份是不确定的**——我们不知道 GLM 赢的
是 arm A，还是一个配置不同的 v_shape。

要查的，按可能性排序：
  (a) GC 校正是否开启（arm A 是开的，见下一节）
  (b) shared_ori 是否为 True（fit_windows 默认 True；设 False 是"有用的
      诊断但更差的估计器"，文档原话）
  (c) anchors_per_window 是否用 "auto"
  (d) 子采样的样本集与随机种子是否与 zheng2020/bench.sh 一致
  (e) 融合是否用了 fusion.fuse（含 min_anchors=30 与 DL 升级）

最省事的判别：用 C8 的 harness 跑一遍 v_shape，看能不能复现
RESULTS.txt 的 arm A 那五行。复现不了就是配置差异，先对齐再比。


2. 阻断项二：5-10x 的退步是遗漏了 GC 项，不是 overdispersion
----------------------------------------------------------------

判据是阴性对照随深度的行为。C8 的 glm 阴性对照：

    0.5x 0.306 | 1x 0.270 | 2x 0.282 | 5x 0.332 | 10x 0.301

**它是平的。** 稳定期样本的假梯度不随深度收缩，这是"偏差"的签名，不是
"方差"的签名。overdispersion 只放大方差。

而且理论上就修不了：
  - quasi-Poisson（Pearson 缩放）的得分方程与 Poisson 完全相同，点估计
    逐位相同，只有 SE 乘 sqrt(phi)。
  - negative binomial 只改权重，去不掉遗漏变量偏差。

模拟验证（真实 GC 结构：GC 与离 ori 距离相关 -0.348，跨度 9.58 个 GC 点，
实测自 data/exemplar_M1_2x_windows.rates.tsv）：

  深度   真值   Poisson 无GC   NB 无GC   Poisson + 固定GC offset
  0.5x   0.0       0.168       0.170          -0.065
  0.5x   1.3       1.484       1.485           1.252
  1.0x   0.0       0.256       0.255           0.022
  1.0x   1.3       1.544       1.542           1.310
  5.0x   0.0       0.223       0.223          -0.010
  5.0x   1.3       1.539       1.540           1.305
 10.0x   0.0       0.223       0.223          -0.011
 10.0x   1.3       1.547       1.547           1.313

NB 与 Poisson 一致到小数点后三位——**选项二不会奏效**。固定 GC offset 在
每个深度都完全修好。而且注意"无GC"那列在有梯度时是 1.48-1.55（真值 1.3），
高估约 0.22，与阴性对照的 0.22-0.26 同量级——同一个偏差项。

对照 C8 的 glm：10x 的 RMSE 0.283 与阴性对照 0.301 同量级，这也符合一个
恒定的加性偏差，而不是随深度缩小的额外噪声。

**请在 c8_wiring.diff 里确认第 4 项接线是否落实**（原任务书原文：
"GC correction becomes an offset ... 在 GLM 里它属于线性预测子中的 offset，
而不是预先调整过的响应"）。当前 pipeline 是把 GC 修正加在 log2_rate 上
（log2_rate_raw -> log2_rate，见 windows.rates.tsv 的 gc_corrected 列）；
如果 GLM 直接吃 total_count，这个修正就完全没有进入模型。

一个实现上的坑：**GC 与位置共线**（相关 -0.348）。所以不能把 GC 当作自由
系数和梯度一起估——它会和梯度争夺同一份变异。要沿用现有做法：GC 修正在
别处单独估计，然后作为**固定 offset**放进线性预测子，系数不再估计。我模拟
里把 GC 当自由参数拟合时结果就不稳定，正是这个原因。


3. 我同意的部分
----------------------------------------------------------------

  - 证伪条件一不成立：低覆盖档 slope 0.26->0.73、0.67->0.82，r 与 RMSE
    同步改善。R4 的"log2 变换压缩"诊断在真实数据上复现了。
  - r2<0 率在 0.5x 从 49.6% 归零，这是 QC 输入质量的实质提升，独立于
    采纳决策，值得单独写进论文。
  - 成本无差异（5.7-31.9s vs 5.9-31.3s，RSS 均 0.18 GB），一致于预期。
  - 170 runs 全部成功，工程上没有问题。


4. 建议
----------------------------------------------------------------

不采纳"深度自适应"，也不做"glm + overdispersion"。按这个顺序：

  1) 对齐 v_shape 基线，直到 C8 harness 能复现 RESULTS.txt 的 arm A。
  2) 确认并修好 GC offset 接线，重跑 C8。
  3) 看重跑后的结果再决定。我的预期是 5-10x 的退步大部分消失，届时
     很可能不需要"深度自适应"这种双估计器方案——但这是预期，不是结论。
  4) 若 GC 修好后 5-10x 仍有残余退步，那时才轮到 overdispersion，
     而且要针对 SE/QC，不要指望它改善点估计。

**Part 9 的重跑暂缓。** 现在启动会基于一个对照组身份不明、且很可能有一个
可修偏差项的比较。sigma_eff 不受影响，继续。

复现本文数字：benches/window_shrinkage.py（stage 3 是 GLM 原型）。本文第 2
节的 GC 模拟未入库，需要的话我可以补成脚本。
